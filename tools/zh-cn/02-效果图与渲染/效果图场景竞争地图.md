# 效果图场景竞争地图

> 文档日期：2026-06-17
> 目的：从工具目录视角梳理效果图与渲染类工具的竞争格局、玩家分层、工作流入口和评测优先级

## 1. 一句话判断

效果图与渲染场景不是一个单一赛道，而是由“通用模型、建筑垂直平台、宿主软件插件、传统渲染软件、后期增强工具、视频生成平台”共同争夺同一张建筑可视化工作流的结果。

竞争的核心不再是“谁的图最好看”，而是：

1. 谁能保留建筑结构；
2. 谁能嵌入建筑师已有软件；
3. 谁能降低从白模到汇报图的修改成本；
4. 谁能提供团队可复用的风格、参数和资产管理；
5. 谁能在商用、隐私、交付规格上进入正式项目。

## 2. 竞争地图总览

```
                     高工作流集成
                          ↑
                          |
      Veras / D5 AI       |      D5 Render / Enscape / V-Ray
      LookX Plugin        |      Lumion / Twinmotion
   插件型 AI 渲染          |      传统渲染工具链
                          |
结构控制强  ←-------------+--------------→ 画面表现强
                          |
      SD / ComfyUI        |      Midjourney / GPT-image
      ControlNet / Flux   |      Krea / Freepik / Leonardo
   可控工作流              |      通用创意生图
                          |
                          ↓
                     低工作流集成
```

这个二维图只解释“结构控制 × 工作流集成”。如果再加第三个维度“传播能力”，Kling、Runway、Pika、Seedance 会从静态效果图赛道外侧切入，成为效果图的下游动态化工具。

## 3. 六类玩家分层

| 层级 | 玩家类型 | 代表工具 | 核心入口 | 竞争优势 | 主要短板 |
|---|---|---|---|---|---|
| A | 通用图像 / 多模态模型 | Midjourney、GPT-image、Gemini / Nano Banana、Freepik、Leonardo | 文本 / 图片 | 审美强、语义强、上手快 | 结构硬控制弱，难进入方案深化 |
| B | 建筑垂直 AI 渲染平台 | LookX、mnml.ai、PromeAI、建筑学长、EVAI | 草图、白模、参考图、模型截图 | 场景贴近建筑、模板和风格库丰富 | 能力差异大，很多仍需实测结构保真 |
| C | 插件型 AI 可视化 | Veras、LookX Plugin、D5 Lite、SketchUp Diffusion | SU/Rhino/Revit/D5 等宿主软件 | 不打断建模流程，天然接近结构数据 | 绑定宿主生态，价格和版本兼容复杂 |
| D | 可控工作流 / 本地部署 | Stable Diffusion、Flux、ComfyUI、ControlNet、LoRA | 本地 GPU / 云端节点 | 结构控制、批量、私有化、可定制 | 学习成本高，不适合零基础用户 |
| E | 传统渲染与实时可视化 | V-Ray、Enscape、Lumion、D5 Render、Twinmotion | 模型 / 材质 / 灯光 / 场景 | 稳定、可交付、行业信任高 | 出图慢，试错成本高，AI 能力多为辅助 |
| F | 后期增强与动态传播 | Magnific、Topaz、Krea、Kling、Runway、Pika、Seedance | 已有效果图 / 图片 / 视频 | 适合展板增强、封面、短片、社媒传播 | 可能改写事实细节或造成建筑形变 |

## 4. 按建筑师工作流的竞争链路

```
概念灵感 → 白模 / 草图 → 结构受控渲染 → 后期增强 → 汇报 / 视频化 → 资产复用
   A          B/C/D             C/D/E             F           F              B/C/E
```

| 阶段 | 用户真实问题 | 主要竞争者 | 决策标准 |
|---|---|---|---|
| 概念灵感 | “我想快速看几个方向” | Midjourney、GPT-image、Nano Banana、Krea | 语义理解、审美、速度、成本 |
| 白模 / 草图 | “我有体块或草图，想变成效果图” | LookX、mnml.ai、PromeAI、建筑学长、EVAI | 结构保持、风格库、上手门槛 |
| 结构受控渲染 | “别乱改我的建筑，只帮我渲染” | Veras、D5 AI、ComfyUI、ControlNet、D5 Render | 几何保真、材质控制、插件集成 |
| 后期增强 | “这张图能不能更清晰、更高级” | Magnific、Topaz、Krea | 保真、放大、局部修复、商用 |
| 汇报 / 视频化 | “能不能做成短片或动态展示” | Kling、Runway、Pika、Seedance | 结构稳定、镜头、时长、水印、商用 |
| 资产复用 | “团队能否复用提示词、风格和历史版本” | 建筑垂直平台、插件平台、传统渲染软件 | 项目管理、预设、权限、导出 |

## 5. 四象限：好看 vs 可控

| 象限 | 特征 | 代表工具 | 适合任务 | 风险 |
|---|---|---|---|---|
| 高审美 / 低可控 | 图好看，结构容易漂移 | Midjourney、部分通用图像模型 | 概念、封面、竞赛氛围 | 不能直接替代方案深化 |
| 高审美 / 高可控 | 同时追求画面和结构 | Veras、LookX、mnml.ai、ComfyUI 工作流、D5 AI（待实测） | 白模转图、方案汇报 | 技术、价格或插件门槛高 |
| 低审美 / 高可控 | 结构稳，但画面需后期 | 传统渲染初稿、部分本地 ControlNet 流程 | 方案推敲、过程图 | 需要 PS / 后期增强补质感 |
| 低审美 / 低可控 | 随机性强，难交付 | 简单 API 换皮工具、低质量模板站 | 尝鲜 | 收录优先级低 |

工具目录评测重点应集中在“高审美 / 高可控”和“低审美 / 高可控”。前者适合推荐，后者适合专业用户和团队流程。

## 6. 四象限：Web 轻工具 vs 插件深工具

| 象限 | 特征 | 代表工具 | 用户价值 | 商业 / 使用风险 |
|---|---|---|---|---|
| Web 轻工具 × 通用模型 | 无安装、快试错 | Midjourney、GPT-image、Krea、PromeAI | 入门快，适合学生和个人探索 | 数据上传、结构漂移、账号 / 支付限制 |
| Web 轻工具 × 建筑垂直 | 建筑模板、草图/白模输入 | LookX Web、mnml.ai、建筑学长、EVAI Web | 更懂建筑任务 | 是否真有结构控制需实测 |
| 插件深工具 × 宿主软件 | 在建模软件内生成 | Veras、D5 Lite、LookX Plugin、SketchUp Diffusion | 最接近设计流程 | 兼容性、订阅、数据上传风险 |
| 本地深工具 × 可控工作流 | 本地 GPU / 节点式流程 | ComfyUI、SD、Flux、ControlNet | 私有化、可控、可批量 | 学习门槛、维护成本、硬件要求 |

## 7. 竞争关系：谁替代谁，谁补充谁

### 7.1 通用模型 vs 建筑垂直平台

通用模型的优势是审美和语义，建筑垂直平台的优势应该是结构控制和工作流。

| 维度 | 通用模型 | 建筑垂直平台 |
|---|---|---|
| 审美探索 | 强 | 中到强 |
| 建筑结构保真 | 弱到中 | 中到强，需实测 |
| 价格透明 | 中 | 差异大 |
| 中文 / 本地化 | 取决于模型 | 国内平台更强 |
| 项目管理 | 弱 | 可能更强 |
| 团队复用 | 弱 | 可能更强 |

结论：通用模型会持续挤压“只会 prompt 模板”的建筑 AI 站；建筑垂直平台必须证明自己在结构控制、插件、项目管理、团队预设或本地化上有增量价值。

### 7.2 插件型 AI vs Web 生图工具

插件型 AI 不一定画得最好，但更接近正式设计流程。

| 维度 | 插件型 AI | Web 生图工具 |
|---|---|---|
| 导入成本 | 低，直接从宿主软件启动 | 需要截图 / 上传 / 下载 |
| 结构上下文 | 可能读取相机、材质、几何、深度 | 多数只看图片 |
| 团队部署 | 受软件版本和 IT 管控影响 | 注册即用 |
| 学习门槛 | 需要会宿主软件 | 更低 |
| 数据风险 | 取决于上传内容和云端处理 | 通常上传图片到云端 |

结论：插件型 AI 更适合设计院和事务所，Web 生图更适合学生、个人设计师和早期概念探索。

### 7.3 插件型工具的深度核验

插件型 AI 的关键问题不是“有没有插件”，而是插件是否把宿主软件中的设计上下文转化为可控输入。后续单工具评测应按以下四层核验，而不是只看插件安装包。

| 核验层级 | 要验证什么 | 低价值表现 | 高价值表现 | 测试方法 |
|---|---|---|---|---|
| 视图层 | 是否只读取当前视窗截图 | 等同截图上传，换个网页也能做 | 能保留相机、透视、构图和图像边界 | 同一模型切换视角，比较输出透视是否稳定 |
| 几何层 | 是否利用体块、边界、深度或遮挡关系 | 层数、洞口、屋顶、道路经常漂移 | 主体体块、层数、开窗和遮挡关系稳定 | 用白模、线框、材质模型分别测试 |
| 材质层 | 是否读取或尊重材质 / 图层 / 对象类别 | 玻璃、石材、木材被大幅重写 | 能在提示词约束下保留关键材料关系 | 指定只改天空或植物，不改主体材质 |
| 迭代层 | 是否支持局部重渲、种子、版本和参数复用 | 每次重画，难以改小问题 | 可局部修改、复用种子或在同一项目中迭代 | 固定一个局部错误，测试是否能低成本修正 |

| 工具 | 当前公开线索 | 深评优先问题 | 初步判断 |
|---|---|---|---|
| Veras | 官方定位为面向 Revit、SketchUp、Rhino、Vectorworks、Archicad 等宿主软件的 AI 可视化插件；公开资料提到 geometry / material override、render selection、same seed 等控制项 | 是否真正利用模型几何和材质信息；云端处理哪些视图 / 模型数据；2D/3D 模式在不同宿主软件中的差异 | 插件深度最高优先级，适合作为 T3 工具样本 |
| D5 Render AI | D5 本身是实时渲染软件，AI 更像嵌入传统渲染链路的增强层；公开资料提到 AI Enhancer、AI Atmosphere Match、AI PBR / 贴图生成等功能 | AI 是前期概念生成、后期增强，还是能改变正式渲染流程；触发 AI 时是否上传截图或场景数据；免费 / Pro 权益边界 | 更适合验证“传统渲染软件 AI 化”，不应简单归为 Web 生图 |
| LookX Plugin | 公开资料显示支持 SketchUp / Rhino 插件，Web 端覆盖草图、参考图、模型截图、风格训练和视频生成 | 插件是否比 Web 上传截图有更强结构保真；团队版项目云盘和私有模型对团队复用是否有价值；免费档生成内容商用限制 | 介于建筑垂直平台和插件型工具之间，适合和 Veras 对照 |
| SketchUp Diffusion | SketchUp 内置 AI 渲染入口，天然贴近 SU 工作流；公开资料称生成图不用于训练且不公开展示，具体以官方条款为准 | 是否适合正式方案深化，还是更偏内置概念草图；与 Veras / LookX Plugin 的控制能力差异 | 可作为“宿主软件官方内嵌 AI”的基准样本 |

这组工具的后续研究顺序建议为：先测 Veras 与 LookX Plugin 的同一 SU 白模任务，再用 D5 Render AI 检查传统渲染链路中的 AI 增强边界，最后用 SketchUp Diffusion 作为低切换成本基准。

### 7.4 传统渲染软件 vs AI 渲染工具

AI 渲染短期不会替代 V-Ray、Enscape、Lumion、D5 Render 的正式交付地位，但会替代一部分前期试风格、快速汇报图和后期增强需求。

| 任务 | 传统渲染更强 | AI 渲染更强 |
|---|---|---|
| 精确材质与灯光 | 是 | 否 |
| 稳定可复现 | 是 | 取决于工具 |
| 快速试风格 | 否 | 是 |
| 白模快速出图 | 中 | 是 |
| 施工 / 报批严肃表达 | 是 | 否 |
| 社媒传播和氛围图 | 中 | 是 |

结论：传统渲染软件会把 AI 做成插件、后期、材质、灯光、资产生成等辅助层；纯 AI 工具则会先吃掉“前期表达”和“低预算效果图”场景。

### 7.5 后期增强 vs 重新生成

后期增强工具的竞争点不是“能否生成新图”，而是能否在不改写事实细节的前提下提高质量。

| 工具类型 | 优势 | 风险 |
|---|---|---|
| Magnific / Krea 类创意增强 | 质感强，适合封面和展板 | 可能重写建筑细节 |
| Topaz 类保真增强 | 本地、保守、保真倾向强 | 创意感不如生成式增强 |
| 重新生成 | 可大幅改变风格 | 原方案细节可能丢失 |

结论：投标图、汇报图和作品集更需要“保真增强”；营销封面和社媒图可以接受更强创意增强。

### 7.6 视频生成工具 vs 建筑动画工具

Kling、Runway、Pika、Seedance 适合把静态效果图变成动态传播素材，但不应与真实漫游动画、施工模拟、BIM 动画等严肃动画混为一谈。

| 维度 | AI 图生视频 | 传统建筑动画 |
|---|---|---|
| 出片速度 | 快 | 慢 |
| 结构稳定 | 弱到中 | 强 |
| 运镜控制 | 中 | 强 |
| 成本 | 低到中 | 高 |
| 正式汇报可信度 | 需筛选 | 高 |
| 社媒传播 | 强 | 中 |

结论：AI 视频工具是效果图的传播延伸，不是建筑动画全替代。

## 8. 国内外玩家差异

| 维度 | 国内工具 | 海外工具 |
|---|---|---|
| 中文提示词 | 通常更友好 | 视模型而定 |
| 支付和访问 | 更稳定 | 可能有网络 / 支付门槛 |
| 教育渠道 | 建筑学长、课程和社群较强 | YouTube / Discord / 英文教程强 |
| 插件生态 | 部分工具正在补 | Veras、LookX、SketchUp Diffusion 等更早 |
| 数据合规 | 国内项目更易解释 | 海外 SaaS 需关注数据出境 |
| 审美风格 | 更贴近国内表达图 | 国际竞赛 / 概念视觉更强 |

## 9. 竞争护城河判断

效果图工具的护城河不只来自底层模型，更多来自“工作流沉淀”。

| 护城河类型 | 强度 | 说明 | 代表方向 |
|---|---|---|---|
| 底层模型 | 高但稀缺 | 自研或深度微调模型，成本高、难验证 | mnml.ai ArchDiffusion（待核验）、通用大模型厂商 |
| 结构控制链路 | 高 | Depth、Canny、Lineart、Segmentation、LoRA、工作流编排 | ComfyUI、ControlNet、LookX / Veras（待实测） |
| 宿主软件集成 | 高 | 读取模型、材质、相机、元数据，比截图上传更难复制 | Veras、D5、SketchUp Diffusion |
| 数据与风格资产 | 中高 | 团队风格库、企业项目素材、LoRA 训练 | Krea、LookX、企业私有化平台 |
| 项目管理与协作 | 中 | 历史版本、团队预设、权限、素材管理 | 垂直平台、传统渲染软件云协作 |
| Prompt 模板 | 低 | 容易复制，很快被通用模型吞噬 | 简单生图站 |
| 积分转售 / API 聚合 | 低到中 | 价格和体验可做优化，但上游依赖强 | 多模型聚合工具 |

## 10. Agent 交叉范围

效果图场景需要单独跟踪一类交叉产品：它们表面上是 AI 渲染、建模或软件插件，但产品逻辑更接近 Claude Code 类 Agent——读取上下文、调用工具、执行多步任务、保留项目状态，并让用户通过权限和版本机制建立信任。

### 10.1 纳入交叉研究的条件

| 条件 | 纳入原因 | 代表样本 |
|---|---|---|
| 读取宿主软件上下文 | 不只是截图上传，而是可能利用模型、相机、材质、图层、对象语义 | Veras、LookX Plugin、SketchUp Diffusion、D5 Lite |
| 能操控设计 / 渲染流程 | 从生成图片扩展到材质、灯光、配景、批量出图或导出 | D5 Render AI、Chaos AI Enhancer、Enscape AI 能力 |
| 支持多步迭代 | 能在同一项目中局部修改、复用参数、保留版本 | Veras、LookX、D5 Studio、Magnific / Freepik Spaces |
| 可连接外部工具或协议 | 具备被 Agent 调用或调用其他工具的潜力 | Magnific MCP、BlenderMCP、RhinoMCP、ComfyUI 工作流 |
| 面向专业软件 Copilot | 自然语言驱动 CAD/BIM/结构/工程软件 | Autodesk Assistant、Bentley Copilot、PKPM Agent |

不满足这些条件的纯生图站、提示词模板站、积分转售站，仍放在效果图工具范围内，但不进入 Agent 交叉研究。

### 10.2 与 Claude Code 类产品的对应关系

| Claude Code 类能力 | 建筑效果图 / 设计软件中的对应物 | 评测指标 |
|---|---|---|
| 代码库上下文 | BIM / CAD / SU / Rhino 模型上下文 | 是否读懂体块、材质、相机、图层 |
| 文件修改 | 模型、材质、视角、渲染参数修改 | 是否可控、可局部修改、可回滚 |
| 终端 / 工具调用 | 插件、渲染器、脚本、节点工作流调用 | 是否稳定执行多步流程 |
| 测试验证 | 结构保真、图纸一致、材质不漂移 | 是否能发现并修正偏差 |
| 权限与沙盒 | 图纸 / 模型上传、训练排除、团队权限 | 是否适合正式项目和企业部署 |
| 项目记忆 | 风格库、材质库、参数、历史版本 | 是否能沉淀团队资产 |
| 后期增强 Agent | 放大、重打光、局部修复、视频/3D/Stock/Flows 工具链 | 是否能从单点增强变成可编排的视觉生产流程 |

## 11. 工具目录收录与评测优先级

### 11.1 优先深评

| 优先级 | 类型 | 工具 | 理由 |
|---|---|---|---|
| P0 | 插件型 / 工作流型 | Veras、D5 Render AI、LookX | 最能解释“AI 渲染是否进入正式工作流” |
| P0 | 建筑垂直 Web | mnml.ai、PromeAI、建筑学长、EVAI | 覆盖学生、个人设计师和轻量设计团队 |
| P0 | 后期增强 Agent | Magnific / Freepik Pikaso | 已有官方远程 MCP、Spaces / Flows 和跨媒体工具链，优先验证是否从 upscaler 变成可编排后期 Agent |
| P0 | 后期增强 | Topaz、Krea | 与汇报图、展板和作品集直接相关，作为 Magnific 对照样本 |
| P1 | 视频动态化 | Kling、Runway、Pika、Seedance | 是效果图场景的下游延伸，适合专题横评 |
| P1 | 可控工作流 | ComfyUI、Flux、ControlNet | 专业用户价值高，也是设计 Agent 的底层工作流样本 |
| P1 | 设计软件 Agent 交叉 | BlenderMCP、RhinoMCP、Autodesk Assistant、Bentley Copilot、PKPM Agent | 不全部归入效果图类目，但用于判断“AI 操控设计软件”的趋势 |

### 11.2 暂缓深评

| 类型 | 暂缓原因 |
|---|---|
| 只提供 prompt 模板的生图站 | 技术和产品差异低，容易过时 |
| 无价格 / 无隐私条款 / 无稳定入口工具 | 难以给建筑师选型建议 |
| 只展示官方案例、无法试用的工具 | 缺乏可验证性 |
| 与建筑场景关系弱的泛视频特效工具 | 可放入观察池，不进入核心效果图类目 |

## 12. 未来 12 个月趋势

1. **通用模型继续上压**：GPT-image、Gemini、Midjourney 等会持续提升文字理解、多图参考和局部修改能力，挤压浅层套壳工具。
2. **插件型工具加速分化**：能读取模型语义和几何信息的插件会进入设计流程，只做截图上传的插件会被 Web 工具替代。
3. **传统渲染软件 AI 化**：D5、Enscape、V-Ray、Lumion 这类工具会把 AI 放进材质、灯光、后期、资产生成，而不是完全放弃传统渲染链路。
4. **后期增强从“变漂亮”转向“保真增强”**：投标和汇报场景更需要不改写事实细节的增强工具。
5. **图生视频成为标配延伸**：效果图工具会越来越多地接入视频生成，但建筑结构稳定性仍是最大短板。
6. **隐私和训练条款成为采购门槛**：设计院和事务所会越来越关心上传图纸、模型和客户照片是否被训练或公开展示。
7. **Agent 化从编程工具迁移到设计软件**：Claude Code 类产品验证了“上下文 + 工具调用 + 权限 + 验证”的工作流，建筑软件会在渲染、建模、BIM、结构和汇报环节复制这套模式。

## 13. 相关论文线索

本节只收录与效果图工具评测直接相关的论文线索，不做完整学术综述。论文的价值在于把“工具宣传语”拆成可验证技术问题：结构控制、参考图一致性、3D 上下文、后期保真、视频稳定性。

### 13.1 结构控制与参考图一致性

| 论文 / 方向 | 研究问题 | 对工具评测的启发 |
|---|---|---|
| [ControlNet: Adding Conditional Control to Text-to-Image Diffusion Models](https://arxiv.org/abs/2302.05543) | 用边缘、深度、姿态、分割等条件控制扩散生成 | 白模转效果图不能只看“好不好看”，应分别测试 Canny、Depth、Lineart、Segmentation 对体块、开窗、道路和水体的保真能力 |
| [T2I-Adapter: Learning Adapters to Dig out More Controllable Ability for Text-to-Image Diffusion Models](http://arxiv.org/abs/2302.08453v2) | 用轻量 adapter 给文生图模型增加结构条件 | 判断工具是否可能是“通用模型 + 控制适配器”路线，而不是自研建筑模型 |
| [IP-Adapter: Text Compatible Image Prompt Adapter for Text-to-Image Diffusion Models](http://arxiv.org/abs/2308.06721v1) | 用参考图作为图像提示，和文本提示共同控制生成 | 解释 LookX、Krea、PromeAI 等“参考图 / 风格图”功能：重点测风格迁移是否会破坏主体几何 |
| [Uni-ControlNet: All-in-One Control to Text-to-Image Diffusion Models](http://arxiv.org/abs/2305.16322v3) | 多种控制条件统一到一个生成框架 | 后续横评应设计多条件样本：白模截图 + 深度 + 风格参考，而不是单一 prompt 测试 |
| [ControlNet-XS: Rethinking the Control of Text-to-Image Diffusion Models as Feedback-Control Systems](http://arxiv.org/abs/2312.06573v2) | 以更小控制模块实现条件控制 | 商业工具可能用轻量控制模块降低推理成本，评测应关注结果稳定性而不是只追问模型名 |

| [DEsignBench: Exploring and Benchmarking DALL-E 3 for Imagining Visual Design](http://arxiv.org/abs/2310.15144v1) | 评估 DALL-E 3 在视觉设计想象任务中的表现 | 可借鉴其 benchmark 思路，把建筑效果图测试拆成任务集，而不是用单张官方案例判断工具能力 |

### 13.3 图像增强与保真修复

### 13.6 视觉 Agent 与 BIM / CAD MCP

| 论文 / 方向 | 研究问题 | 对工具评测的启发 |
|---|---|---|
| [AgentVista: Evaluating Multimodal Agents in Ultra-Challenging Realistic Visual Scenarios](https://arxiv.org/abs/2602.23166v2) | 多模态 Agent 在真实视觉任务中如何长链路调用工具 | 交叉 Agent 评测不能只看单次出图，应加入多图输入、搜索、观察反馈、失败恢复和长任务收敛 |

### 13.7 对后续研究的影响

1. **固定样本需要从单图扩展到多条件**：白模截图、线稿、深度、参考风格、局部修改应分别测试。
2. **“结构保真”要拆成几何、材质、语义和时序**：静态图看体块和开窗，增强图看细节是否被重写，视频看跨帧一致性。
3. **插件型工具要验证宿主上下文**：如果插件只是截屏上传，其能力应归入 Web 生图；如果能利用几何、材质、相机和版本状态，才接近设计软件 Agent。
4. **Agent 工具链要验证闭环**：后期增强和设计软件 MCP 要记录工具选择、输入输出、失败恢复、权限提示、credits 消耗和版本回退。
5. **论文路线不等于产品能力**：论文证明技术可行，工具评测仍要以官方条款、实测样本、商用限制和隐私处理为准。

### 13.8 本轮论文检索复盘

| 结论 | 说明 | 对文档体系的影响 |
|---|---|---|
| 通用可控生成论文足够支撑评测框架 | ControlNet、T2I-Adapter、IP-Adapter、Uni-ControlNet 等已经能解释大多数“白模 / 线稿 / 参考图控制”能力 | 后续单工具评测不必追逐所有模型名，重点看工具是否把这些控制能力产品化 |

| 交叉 Agent 论文已经形成三条主线 | AgentVista、Agent-X、VTC-Bench 对应视觉 Agent 基准；GenAgent、PhotoAgent 对应视觉生产 Agent；Qwen-BIM、MCP4IFC 对应建筑软件 Agent | 交叉 Agent 专题应优先围绕“视觉工具链、后期增强闭环、BIM / CAD MCP”三条线展开 |

## 14. 阶段复盘

### 14.1 已完成

1. **场景边界从“AI 生图”收敛为“建筑可视化工作流”**：已区分概念、白模转图、插件渲染、后期增强、视频动态化和 Agent 交叉范围。
2. **竞争地图从玩家罗列升级为评测框架**：已形成玩家分层、工作流链路、好看 vs 可控、Web vs 插件、护城河和深评优先级。
3. **插件型工具有了可验证口径**：已建立视图层、几何层、材质层、迭代层四级核验，避免只看插件安装包。
4. **论文线索已转化为实测指标**：结构控制、参考图一致性、后期保真、图生视频稳定、单图到 3D 都已对应到测试观察点。
5. **Agent 论文脉络已接入评测框架**：视觉 Agent、图像编辑 Agent、BIM / CAD MCP 已分别对应到多步规划、工具链闭环、宿主上下文和验证机制。
6. **Agent 交叉范围已纳入效果图趋势**：Magnific / Freepik Pikaso、BlenderMCP、RhinoMCP、Autodesk Assistant 等可作为后续观察样本。

### 14.2 当前不足

1. **P0 单工具评测仍未补齐**：LookX、mnml.ai、PromeAI、Veras、D5 Render AI、Krea、Topaz、Kling、Runway、Pika 还停留在研究计划和竞争地图层。

3. **固定样本尚未落地**：S1-S6 样本还只是测试方案，没有形成可复用素材包和结果记录表。
4. **建筑专门论文还需要补查**：当前论文线索偏通用生成、增强和视频，建筑立面、室内布局、PBR 材质和 3D 场景编辑需要继续补。
